## Popup accessibility evidence

The popup keeps one semantic `tablist`, three named `tab` controls, a labelled `tabpanel`, and a polite live region. Runtime tests cover top-level arrow navigation, focused-flow locking, focused exit, grammar feedback, click-only token correction, and every visible action's accessible name. The layout contract covers:

- semantic buttons with `type="button"` and stable accessible text or labels;
- logical roving tab order and visible focus;
- Enter/Space-compatible native button activation;
- `role="status"` grammar and saved-feedback announcements;
- 44-pixel lesson/filter/sort controls and 48-pixel primary controls;
- reduced-motion support;
- fixed narrow-popup containment with vertical internal scrolling and hidden horizontal overflow.

The real-browser pass must still confirm the same behavior with keyboard-only focus and a narrow popup in both generated artifacts. That pass is recorded by the independent human gate below rather than inferred from DOM tests.

## Encounter Coaching evidence

The existing webpage lookup and tooltip seams prove that grammar coaching:

- recognizes only exact normalized reviewed subject-plus-form pairs for an Introduced pattern;
- stays silent for unstudied, ambiguous, cleared, stale, disabled, or failed lookups;
- does not scan a page or inspect unrelated text;
- adds no translation-provider request when practice starts, retries, or completes;
- keeps dismissal, Escape, scrolling, focus return, keyboard controls, and live feedback on the tooltip seam; and
- persists only the existing bounded learning encounter or canonical evidence contract, never raw selected sentences, URLs, answers, response times, or full attempts.

Evidence lives in `src/content/webpage-lookup-module.test.ts`, `src/content/tooltip-view-adapter.test.ts`, and the typed learning/message tests.

## Privacy and safe-failure boundary

Grammar data remains inside the local versioned learning record. It stores compact pattern evidence, scheduling, bounded misconception counters, recent exercise identifiers, and the current mixed Daily Five snapshot. It does not store raw webpage text, selected sentences, URLs, response timing, raw answers, full attempt histories, session timelines, or behavioral analytics.

Invalid grammar content is rejected before grammar messages, grammar scheduling, or grammar result writes. Existing lesson progress, saved vocabulary, normal translation, backup validation, and the twelve published lessons retain their safe paths. Storage failures return explicit errors and do not report false success. Versioned import validates before mutation, and Clear removes grammar data together with the existing local learning record.

## Independent human validation handoff

T08 / #89 owns the remaining release decision:

1. A second fluent Dutch reviewer with grammar-teaching competence checks every generated sentence, answer, alternative, distractor, explanation, feedback item, source, and provenance entry.
2. A voluntary, data-minimized pilot includes 6–10 target learners, including at least three genuine A0/Pre-A1 learners.
3. Participants complete a short baseline, the supported lesson/Daily Five flow, and a reviewed unseen or recombined delayed check 2–7 days later.
4. Usability passes only when at least 80% complete the core flow without moderator intervention, understand correction, and retain prior lesson progress.
5. The directional learning gate requires delayed median first-Check performance above baseline and a lower targeted misconception rate.
6. Encounter Coaching is reviewed separately for disruption, false positives, dismissal, and zero incremental provider requests.

The reviewer records findings, limitations, reviewer/date, deviations, and a release/revise decision. Until that record exists, this document describes engineering readiness for review and does not claim Dutch proficiency or product efficacy.
